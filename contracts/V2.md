# V2 改造契约（并行开发唯一真源）

> 本轮目标：全站登录门禁、收藏/投递状态云端化、采集收敛为 live、发布工程补全。
> 与 V1 的差异处均已标注「变更」，未标注的保持原样。

---

## 0. 全局决策（主控已定，勿改）

1. **鉴权只保留应用层**：nginx 的 `auth_basic` 全部移除，由应用统一验证。
2. **`/` 与 `/admin` 仍然是公开可取的静态外壳**（内部不含任何数据），真正的数据接口全部要求登录。
   前端在 `/api/auth/me` 返回未登录时展示登录卡片——这就是「访问首页需要登录」的落地方式。
   这样做的原因：登录页要能被匿名访问，否则 302 会打断登录流程。
3. **会话共享**：登录一次，`/` 与 `/admin` 同时生效。admin 角色在 `/` 上直接看到「管理后台」入口，
   进入 `/admin` 无需二次登录。
4. **`/api/health` 保持公开**（用于监控探活），其余 `/api/*` 全部要求登录。
5. 零第三方依赖不变；Go 1.22+；中文注释；导出符号必须有 doc comment。

## 2. F1 · 用户数据云存储

### 2.1 数据形状（契约）

```jsonc
// data/userstate/<username>.json，权限 0600，目录 0700
{
  "version": 1,
  "favorites": ["manual:abc123", "boss:xyz"],   // 岗位 ID 列表，去重
  "stages": { "manual:abc123": "applied" },      // 岗位 ID -> 阶段
  "notes":  { "manual:abc123": "约了下周三面试" }, // 岗位 ID -> 备注
  "updatedAt": "2026-11-26T14:30:00Z"
}
```

- 阶段取值白名单：`""`（未投递）/ `applied`（已投递）/ `interview`（面试中）/ `offer`（已发 offer）/ `rejected`（已拒绝）。
  非法值一律归一为 `""`。
- `notes` 单条 ≤ 500 字符（按 rune 截断），`favorites` 最多 5000 条，`stages`/`notes` 最多 5000 键。
- 文件不存在 = 空状态，**不是错误**。

### 2.2 包接口

```go
package userdata

type State struct {
    Version   int               `json:"version"`
    Favorites []string          `json:"favorites"`
    Stages    map[string]string `json:"stages"`
    Notes     map[string]string `json:"notes"`
    UpdatedAt string            `json:"updatedAt"`
}

func NewState() State

type Store struct{ /* dir, mu */ }
func NewStore(dir string) *Store                 // dir 形如 <data>/userstate
func (s *Store) Path(username string) string
func (s *Store) Load(username string) (State, error)   // 不存在 → 空 State
func (s *Store) Save(username string, st State) (State, error) // 原子写、归一化、补 UpdatedAt
func (s *Store) Delete(username string) error          // 幂等
```

- `username` 必须先经 `auth` 的规范化规则（小写 + `[a-z0-9._-]{3,32}`），非法直接返回错误，**禁止拼路径穿越**。
- 原子写：临时文件（0600）+ `os.Rename`；目录 `MkdirAll 0700`。
- 并发安全（`sync.RWMutex`）。

### 2.3 HTTP 接口（`internal/web/userstate_api.go`）

```go
func (s *Server) handleGetMyState(w http.ResponseWriter, r *http.Request) // GET /api/me/state
func (s *Server) handlePutMyState(w http.ResponseWriter, r *http.Request) // PUT /api/me/state
```

- 用户名取自会话（`s.currentSession` / `authenticate`），**不接受客户端传入用户名**。
- GET → `200 {"ok":true,"state":{...}}`；用户尚无数据时返回空 State（200，不是 404）。
- PUT → body 即 State（忽略其中的 `version`/`updatedAt`，由服务端重算），返回 `200 {"ok":true,"state":{...}}`。
- 契约外的键一律忽略；类型错误 → `400 {"ok":false,"error":"BAD_REQUEST"}`；超限 → `422 {"ok":false,"error":"VALIDATION_FAILED","fields":{...}}`。
- 主控会在 `server.go` 用 `requireAuth` 包裹这两条路由，你只写 handler。

### 2.4 验收

`go test ./internal/userdata/` 必须覆盖：空文件、往返一致、归一化（非法阶段/超长备注/重复收藏/超量截断）、
路径穿越拒绝（`../x`、`a/b`、空）、并发读写、原子写后文件权限 0600（非 Windows）。

## 4. F3 · 前端

### 4.1 `index.html` 改动清单

**① 登录门禁（新增）**
- 首屏调用 `GET /api/auth/me`：
  - `authenticated:true` → 正常渲染工作台，顶栏显示用户名与角色；`admin` 额外显示「管理后台」入口（`/admin`）。
  - `authenticated:false` → 显示**居中登录卡片**（复用 admin.html 的视觉：品牌标 + 标题 + 用户名/密码 + 提交按钮 + 错误行），
    工作台主体隐藏。错误文案与状态码对齐 admin.html：401 → 「用户名或密码不正确」，429 → 「尝试过于频繁，请 60 秒后再试」，
    `AUTH_NOT_INITIALIZED` → 提示先创建管理员账号。
  - 登录成功后无需刷新，直接进入工作台。
- 顶栏新增「退出登录」入口（`POST /api/auth/logout` 后回到登录态）。
- 所有 `fetch` 携带 `credentials:"same-origin"`；任何接口返回 401 → 切回登录态并提示。

**② 删除指定文案（逐字删除，不要留空容器）**
- `<div class="brand__sub" id="brandSub">BOSS直聘 · 薪资明文</div>` —— 整个节点删除（含其在渲染逻辑里对 `brandSub` 的赋值）。
- 页脚 `footerMeta` 的「数据来源：…合规提示：…」整段说明删除；`renderFooter` 里拼接该文案的代码一并删除，
  只保留必要的极简信息（如更新时间），不得残留「内置示例数据」「robots.txt」「个人求职」等字样。

**③ 收藏与投递状态改为云端（核心）**
- 删除 localStorage 作为**权威存储**的做法，改为一律读写 `GET/PUT /api/me/state`。
- 数据形状见 §2.1：`favorites` / `stages` / `notes`。
- 保存策略：任何变更后 **800ms 防抖自动保存**；同时提供「立即保存」按钮；顶栏显示保存状态（已保存 / 保存中 / 保存失败）。
- `localStorage` 仅可作为**页面级缓存**用于首屏秒开（可选），但必须以后端返回为准覆盖，且提交前必须成功读取后端状态。
- 保存失败：toast 报错 + 状态标红 + 保留本地改动，下次变更或点「立即保存」时重试。
- 切换账号：退出登录时必须清空内存态与缓存，避免串号。

**④ 采集面板**
- 去掉模式选择（sample/local/live）与文件路径输入，只剩「关键词 / 城市 / 页数 / robots 放行开关」。
- 请求体改为 `{query, city, pages, allowDisallowed}`（**去掉 mode**）。
- robots 开关文案保留「勾选后才会真正放行被 robots 禁止的路径」的风险提示。

### 4.2 `admin.html` 改动

- 「返回前台」链接保留；若当前已登录则不再重复要求登录（会话共享，无需改逻辑，确认即可）。
- 顶部增加「当前账号：xxx」已具备，无需新增。
- 仅当与 `index.html` 的登录卡片文案不一致时对齐，别做无关重构。

### 4.3 约束

- 单文件、全内联、零外链、SVG 图标、零 emoji；沿用现有设计令牌。
- 唯一刷新入口 `refreshAll()`，渲染函数之间禁止互调（铁律 9）。
- 所有插值必须转义。
- 不得引用 `data/samples` 之类已删除的静态资源。

### 4.4 验收

- 未登录：只见登录卡片，看不到岗位列表、看不到任何计数。
- 登录后：列表正常，收藏/投递/备注改动后 1 秒内落库（可在 Network 里看到 `PUT /api/me/state`）。
- 换浏览器/清缓存后重新登录，收藏与状态仍在（证明在服务端）。
- 页面内 `grep` 无「薪资明文」「内置示例数据」「robots.txt」残留。
- 无控制台报错；390px 视口无横向滚动。

## 5. F4 · 发布工程

### 5.1 变更日志分类（`scripts/release-notes.sh`）

按 Conventional Commits 分组，输出 markdown：

```markdown
## 新增
- 登录门禁：首页与后台统一登录，admin 登录后直达管理端 (a1b2c3d)
## 修复
- 未创建账号时提示「未初始化」而非密码错误 (d4e5f6a)
## 优化
- 采集面板去掉模式选择，减少一次点击 (b7c8d9e)
## 其他
- chore: ... (仅当存在未归类提交时输出该小节)
```

- 判定：`feat` → 新增；`fix` → 修复；`perf`/`refactor`/`style`/`docs`/`test`/`build`/`ci`/`chore` → 优化；
  `BREAKING CHANGE` 与 `!:` 在对应条目后追加 `**（不兼容变更）**`。
- 区间 = `最近 tag..HEAD`；无 tag 时取全部历史（限最近 50 条）。
- 每条格式 `- <去掉 type 前缀的描述> (<短 SHA 7 位>)`；同一分类内按提交时间倒序。
- 空分类不输出该小节；全部为空时输出 `- 本次发布无用户可见变更`。
